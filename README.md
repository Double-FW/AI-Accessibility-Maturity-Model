# AI Accessibility Maturity Model

A model to replace current compliance-led accessibility maturity models (AMMs).

This repository contains a framework for embedding accessibility, inclusion, governance, and comparable human experience into AI-enabled organisations.

## Why this repository exists

Traditional accessibility maturity models were designed for relatively stable digital environments and often focus on compliance, audits, and isolated remediation. In AI-enabled organisations, accessibility risks emerge not only from technical accessibility issues but also from:

- AI governance gaps
- automated decision-making
- operational assumptions
- procurement decisions
- inaccessible data and workflows
- exclusionary design patterns
- weak organisational accountability

This model reframes accessibility maturity as an organisational capability for producing inclusive outcomes consistently across customer experience, employee experience, service delivery, AI systems, and governance structures.

## Core principles

The model is built around the following principles:

- Accessibility is organisational infrastructure, not a standalone specialist activity.
- Comparable experience is the primary outcome, not simply technical compliance.
- AI systems are part of accessibility governance.
- Accessibility maturity is continuous and must evolve with technology and organisational change.

## The six maturity dimensions

The model evaluates organisations across six dimensions:

1. Leadership and Governance
2. Culture and Capability
3. Design, Delivery, and Operations
4. Data, Measurement, and Comparable Experience
5. AI, Automation, and Intelligent Systems
6. Ethics, Risk, and Organisational Trust

## The five maturity levels

The model uses five maturity levels:

1. Reactive
2. Foundational
3. Operational
4. Integrated
5. Transformative

## What the model aims to assess

The framework is intended to help organisations assess whether inclusion is genuinely embedded into:

- governance and leadership
- culture and capability
- operational processes and service design
- AI and automation practices
- data collection and measurement
- decision-making and trust frameworks

It is designed to evaluate both organisational capability and the lived experience of disabled people.

## How to use the model

The model should be used as a strategic assessment tool rather than a simple scoring exercise. It is intended to:

- identify strengths and gaps
- expose governance weaknesses
- assess AI readiness
- evaluate operational alignment
- improve comparable experience
- guide long-term transformation

Recommended inputs include:

- governance review
- operational evidence
- stakeholder workshops
- customer and employee insight
- journey analysis
- AI system evaluation
- accessibility testing
- cultural assessment

## Measuring success

A mature accessibility programme does not only measure technical compliance. It also evaluates:

- customer satisfaction
- employee confidence
- support burden and friction
- complaint trends
- abandonment patterns
- inclusion indicators
- AI outcome quality
- governance evidence

This reflects the model's emphasis on lived experience and equitable outcomes.

## Repository purpose

This repository is intended to support organisations seeking to move beyond compliance-led thinking and build more resilient, inclusive, and AI-ready accessibility practices.

The goal is not simply to meet standards, but to create systems and operating models that consistently deliver fair, dignified, and trustworthy experiences for disabled people.
